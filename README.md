# VoltSound · V8 GPS Edition

Tesla Model 3-ის ჰორიზონტალური ეკრანისთვის შექმნილი სინთეზირებული V8 და GPS დიაგნოსტიკა. აპი იყენებს Next.js App Router-ს, TypeScript-სა და Tailwind CSS-ს. სიჩქარეს ბრაუზერის Geolocation API-დან იღებს, ხმას ადგილზე ქმნის და სერვერზე მონაცემებს არ აგზავნის. აპს ანგარიში, გამოწერა ან ფასიანი API არ სჭირდება.

## V8-ის გამოცდა

1. გაჩერებულ Tesla-ში გახსენი ძირითადი HTTPS მისამართი. **Engine sound**-ში აირჩიე **Shelby GT500 ’70** ან **C63 AMG W204**, შემდეგ აირჩიე **Manual Mode** და დააჭირე **Start Sound**. Shelby-ს პრესეტს ღრმა და ოდნავ არათანაბარი ხმა აქვს, C63-ის პრესეტს კი უფრო მკვეთრი ტემბრი. ორივე ხმა სინთეზირებულია და პრესეტებს შორის გადართვა დაკვრის დროსაც შეგიძლია.
2. შეცვალე **Target RPM** ან დააჭირე **Rev**. ხმამაღლობას **Volume**-ით მართავ, დაკვრას კი **Stop Sound** აჩერებს.
3. GPS-ისთვის აირჩიე **GPS Drive**, დაუშვი ლოკაციაზე წვდომა და მგზავრობისას დააკვირდი RPM-სა და ვირტუალურ გადაცემას. მოძრაობისას ეკრანს მხოლოდ მგზავრი მართავს. დიაგნოსტიკა ხელმისაწვდომია **GPS Diagnostic** ბმულით ან `/diagnostic/` მისამართზე.

ვირტუალური კოლოფი ექვსსაფეხურიანია. აპი სიჩქარის განახლებებს შორის ინტერვალებით აფასებს აჩქარებას და RPM-ისთვის იყენებს მაქსიმუმ 300 ms-ის პროგნოზს. თუ სიჩქარის ახალი ნიმუში 1.25 წამს არ მოვა, ძრავა რბილად უბრუნდება უქმ სვლას. გვერდის დამალვისას აპი ხმას აჩერებს.

ნაგულისხმევად ხმა იკვრება Web Audio-თი. **Try AudioWorklet** ჩართე ხმის გაშვებამდე, თუ ამ გზის გამოცდა გინდა. ჩატვირთვის ან დამუშავების შეცდომის დროს დაკვრა სტანდარტულ Web Audio-ზე გადადის. პედლიდან დინამიკამდე რეალური დაყოვნება მანქანაში უნდა გაიზომოს.

## ლოკალურად გაშვება

1. ამოარქივე პროექტის ZIP და გახსენი საქაღალდე VS Code-ში.
2. დააყენე Node.js 22 ან უფრო ახალი ვერსია.
3. VS Code-ის ტერმინალში გაუშვი:

```sh
npm ci
npm run dev
```

გახსენი [http://localhost:3000](http://localhost:3000). Windows PowerShell-ში, თუ `npm.ps1` დაბლოკილია, იმავე ბრძანებებში გამოიყენე `npm.cmd`.

სტატიკური ვერსიისა და შემოწმებების გაშვება:

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

`npm run build` ქმნის `out/` საქაღალდეს. `npm run preview` მას ემსახურება [localhost:3000](http://localhost:3000)-ზე. ჯერ გააჩერე dev სერვერი, თუ ის იმავე პორტზე მუშაობს. `localhost` დეველოპერის კომპიუტერზე უსაფრთხო კონტექსტად ითვლება. მანქანიდან გასახსნელად გამოიყენე საჯარო HTTPS მისამართი. [Next.js-ის სტატიკური ექსპორტი](https://nextjs.org/docs/app/guides/static-exports)

## განთავსება უფასო HTTPS ჰოსტინგზე

1. გაუშვი `npm ci` და `npm run build`, ან ამოარქივე ცალკე მოწოდებული სტატიკური ZIP.
2. შედი [Netlify Drop-ში](https://app.netlify.com/drop) და ატვირთე მზა საქაღალდე, რომლის უშუალო შიგთავსშია `index.html`, `audio-probe.js` და `_next/`. ლოკალური ბილდის შემთხვევაში ესაა `out/`.
3. თუ პროექტს წვდომის შეზღუდვა აქვს, შეცვალე მისი ხილვადობა ისე, რომ Tesla-ს ბრაუზერმა გვერდი ავტორიზაციის გარეშე გახსნას. მანქანის ბრაუზერში გახსენი Netlify-ის მინიჭებული `https://….netlify.app` მისამართი. [ატვირთვის ინსტრუქცია](https://docs.netlify.com/start/quickstarts/netlify-drop-quickstart/) · [HTTPS](https://docs.netlify.com/manage/domains/secure-domains-with-https/https-ssl/)

აპს გამოყენების საკუთარი კვოტა არ აქვს. Netlify-ის უფასო გეგმაზე ჰოსტინგს თვიური კრედიტების ლიმიტი აქვს. [Netlify-ის გეგმები](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/credit-based-pricing-plans/)

## GPS დიაგნოსტიკა Tesla-ში

1. გაჩერებულ მანქანაში გახსენი **GPS Diagnostic**, დააჭირე **Start Test** და დაუშვი ლოკაციაზე წვდომა. ბრაუზერმა შეიძლება ცალკე მოითხოვოს მოძრაობის სენსორებზე წვდომა.
2. აიღე რამდენიმე ნიმუში გაჩერებულ მდგომარეობაში, შემდეგ კი ჩაატარე მოკლე მგზავრობის ტესტი მსუბუქი აჩქარებით, თანაბარი სიჩქარით და შენელებით. მოძრაობისას ეკრანს მხოლოდ მგზავრი მართავს. თუ ნებართვა უარყოფილია, შეცვალე საიტის ლოკაციის პარამეტრი და დაიწყე ახალი სესია.
3. დააჭირე **Stop Test**, შემდეგ **Photo Report**. ეკრანზე გამოჩნდება GPS-ის, სიჩქარის, სენსორებისა და აუდიოს შეჯამება. ტელეფონით გადაუღე ფოტო მთლიან ანგარიშს და ჩატში მიამაგრე. იმავე მისამართზე დაბრუნებისას **Last Photo Report** გახსნის ბოლოს შენახულ ანგარიშს, თუ ბრაუზერის მეხსიერება ხელმისაწვდომია.

**Export JSON** შეგიძლია გამოიყენო ყველა ნიმუშისა და მოვლენის ჩამოსატვირთად. **Photo Report**-ში `p95` აღნიშნავს მნიშვნელობას, რომლის ტოლი ან ნაკლებია გაზომვების სულ მცირე 95%. callback-ის წყვეტების რაოდენობაში შედის დასრულებულ განახლებებს შორის გრძელი შუალედები და ბოლო განახლებიდან ტესტის გაჩერებამდე არსებული გრძელი შუალედი.

## შედეგების წაკითხვა

| ველი | რას ზომავს |
| --- | --- |
| `speedKmh` | `coords.speed × 3.6`. `null` ნიშნავს, რომ ბრაუზერს ამ ნიმუშში სიჩქარე არ მოუცია. 0 რეალური ნულოვანი მნიშვნელობაა. |
| `callbackIntervalMs` | ზედიზედ ორი წარმატებული callback-ის შუალედი მონოტონური საათით. |
| `rawPositionTimestamp` | ბრაუზერისგან მიღებული დროის ნიშნული, უცვლელად. |
| `positionIntervalMs` | ორი პოზიციის ამოცნობილი Unix დროის ნიშნულების სხვაობა მილიწამებში. 0 ნიშნავს, რომ დროის ნიშნული განმეორდა. თუ რომელიმე ნიშნული დაუდგენელია, მნიშვნელობაა `null`. |
| `dataAgeMs` | მიღების დროისა და პოზიციის ამოცნობილი Unix დროის ნიშნულის სხვაობა. ნიშნული გამოიყენება, თუ მილიწამებში ან მიკროწამებში მიღების დროსთან 24-საათიან დიაპაზონში ჯდება. სხვა ფორმატისთვის მნიშვნელობაა `null`. პედლიდან დინამიკამდე დაყოვნებას სხვა გაზომვა სჭირდება. |
| `accuracyM` | ბრაუზერის შეფასებული ჰორიზონტალური პოზიციის სიზუსტე მეტრებში. |
| `events` | შეცდომები, სიგნალის დაკარგვა და აღდგენა, გვერდის ხილვადობის ცვლილებები და სენსორების შემოწმების შედეგები. |

Watchdog აჩვენებს **Signal lost**, თუ პირველ პოზიციას 12 წამში ვერ იღებს, ბოლო callback-იდან 5 წამი გადის, ან პოზიციის ამოცნობილი Unix დროის ნიშნული სულ მცირე 5 წამისაა. დაუდგენელი დროის ნიშნულის შემთხვევაში მონიტორინგი ეყრდნობა callback-ებს. მიღებული პოზიციის შემდეგ `POSITION_UNAVAILABLE` ასევე აჩვენებს დაკარგულ სიგნალს. გაჩერებულ ან ფონურ გვერდზე ბრაუზერს შეუძლია განახლებები შეაყოვნოს. ნებართვის უარყოფა ცალკე ჩანს და GPS-ის მონიტორინგი წყდება. [Geolocation API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API/Using_the_Geolocation_API)

**Available** ნიშნავს API-ის აღმოჩენას. **Verified** ნიშნავს, რომ Geolocation-მა პოზიცია დააბრუნა, DeviceMotion-მა რიცხვითი აჩქარება მოგვაწოდა, AudioContext გადავიდა `running` მდგომარეობაში, ან AudioWorklet-მა უხმო აუდიოკადრი დაამუშავა. **No data** DeviceMotion-ზე ნიშნავს, რომ 6 წამში აჩქარების ვერცერთი კომპონენტი ვერ მივიღეთ. თუ მონაცემი მოგვიანებით მოვიდა, სტატუსი განახლდება. AudioContext-ის დაყოვნებები ბრაუზერის შეფასებებია. უხმო შემოწმება დინამიკებიდან გამოსულ ხმას არ ზომავს. [DeviceMotion-ის ნებართვა](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEvent/requestPermission_static) · [AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Using_AudioWorklet)

JSON-ში შედის მიმდინარე სესიის ყველა GPS ნიმუში, მოვლენები, ბოლო აჩქარების ვექტორები, აჩქარების მოვლენების რაოდენობა, აუდიოს შედეგები და ბრაუზერის user agent. გრძედი და განედი ანგარიშში არ ინახება.
